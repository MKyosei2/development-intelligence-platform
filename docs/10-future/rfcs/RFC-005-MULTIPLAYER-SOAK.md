# RFC-005: マルチクライアント・長時間負荷を用いたQAの実証

**Status: Proposed** | **Area: Game QA / Performance**

## 解決する問題

Latency/Jitter/Lossのパラメータを解釈できることと、実ネットワーク下の複数ゲームクライアントで状態同期が保証されることは異なる。長時間のメモリ消費やCPU負荷も、実ワークロード・実環境で再現して初めて結果を解釈できる。

## 方式案

- **Multiplayer:** 専用サーバー＋複数クライアントを隔離環境で起動し、network impairmentを注入する。
- **State:** Tick、Authoritative hash、Client hash、Desync最初の時刻、接続復旧結果を記録する。
- **Soak:** CPU、Memory、GC、Disk、Net、GPU（取得可能時）を連続サンプリングする。
- **Determinism:** Seed、マップ、入力、クライアント数、ビルドSHA、テスト期間を固定する。
- **Risk:** エラーが発生したプロセスだけでなく、同一テストの全クライアントの終了状態を確認する。

## 受け入れ条件

- [ ] 少なくとも正常・意図的desync・切断／復帰ケースを再現。
- [ ] 実マルチクライアントと、テレメトリパーサの単体テストを区別。
- [ ] 失敗／未実行を隠さず、リソースの欠測率も記録。
- [ ] 実行環境、期間、p95/p99、Peak、Recoveryを報告。
- [ ] 結果が対象ビルドとDIP側のSHAへ対応付けられる。

## 未決定事項

最小対応ゲーム、ネットワークエミュレーション方式、必要なRunner分離、実環境トラフィックを利用する場合のプライバシー保護。
