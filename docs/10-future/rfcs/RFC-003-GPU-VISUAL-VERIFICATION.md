# RFC-003: GPU実測・描画回帰の統合検証

**Status: Proposed** | **Area: Game QA / Graphics Performance**

## 問題

PNGの比較、GPU数値のパーサ、静的なシェーダーチェックは互いに補完関係にある。描画が視覚的に正しいか・速いか・安定しているかを、一つのスコアだけで正確に説明することはできない。

## 提案

1. ゴールデンシーンを用意し、撮影条件と対象ビルドを固定する。
2. 画像差分、領域別SSIM、意図したMask、色空間を検証する。
3. 実GPUのFrame Time（平均以外にp95/p99、hitch）とVRAMを測定する。
4. 外部GPUキャプチャが利用できる場合はPass/Markers/Capture fileを保存し、実体とhashを確認する。
5. 性能Budget、視覚差分、収集失敗を別カテゴリで表示する。
6. QA結果を対象SHAへ紐付け、性能の差が再現可能か複数回検証する。

## 比較する方式

- Pixel diff: 差異位置が明瞭だが抗エイリアス等に敏感。
- SSIM: 視覚構造に寛容だが意味的な退行を見逃す可能性。
- GPU telemetry: 速度と負荷を捉えるが視覚的な正しさは判断できない。
- Professional capture: 原因の深掘りに有効だがツール・環境が限定的。

## Acceptance criteria

- [ ] GPU名、Driver、描画API、解像度、Render設定、Target SHAが記録される。
- [ ] 実機不在時にGPU実測成功を主張しない。
- [ ] 空のキャプチャ、無関係なキャプチャ、旧版の結果を拒否できる。
- [ ] 正常・意図的な視覚退行・非決定的エフェクトのPrecision/Recallを測る。
- [ ] 負荷・温度・電源設定による測定ばらつきを明示する。

## 未決定事項

対応GPUとOS、GPUキャプチャツール、外部ツールの利用規約、グラフィックQA結果の人手による承認基準。
