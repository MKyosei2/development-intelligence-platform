# QA-003: ゲームプレイ・ネットワーク・保存互換性

**Status: Proposed** | **対象:** 実ゲームを使った品質確認

## 1. 最小の決定的ゲームシナリオ

- 固定シードで入力・移動・当たり判定・イベントを記録し、同じターゲットビルドでリプレイする。
- 期待状態はゲーム側の仕様として定義し、結果ログの存在だけで成功としない。
- Physicsの差異や可変フレーム時間は許容誤差と再現条件を文書化する。

## 2. マルチプレイヤー

- 2台以上の実クライアント／独立プロセスを用いた同期検証。
- latency、jitter、loss、reordering、disconnect/reconnectを明示的に注入。
- server tick / client tick / state hash / authoritative state / divergence timestampを記録。
- 仮想的な疑似遅延・telemetryのパーサ検証と、実ネットワーク環境の再現を区別する。

## 3. 保存・アップグレード互換性

- 旧バージョンのセーブデータを新ビルドで読み込み、互換性と異常系を判定する。
- 保存途中の電源断、破損ファイル、文字コード、クラウド同期、移行処理を扱う。
- 特定の作品固有ルールがない部分は、共通QAで「未評価」と表現する。

## 4. 入力・ローカライズ・アクセシビリティ

ゲームパッド、キーボード、タッチ、キーバインド、字幕、テキスト量、色覚対応等を実機条件で検証する。業界ガイドラインをチェックリストとして採用する場合、出典・版・対象プラットフォームを必ず明記する。

## 5. 検証条件

対象ビルド、プラットフォーム、デバイス、ネットワーク条件、テストスクリプト、期待状態、失敗証拠、再現回数を残す。CI上の契約テストのみを実機ゲームプレイの成功実績として扱わない。
