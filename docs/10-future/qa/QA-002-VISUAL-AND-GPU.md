# QA-002: ビジュアル・GPU品質検証の構想

**Status: Proposed** | **対象:** ゲームの描画とGPU性能

## 1. 判定器を複数の層に分ける

1. **静的ルール:** シェーダーのコンパイル・設定、アセットの参照、解像度・フォーマットなど。
2. **Golden画像比較:** 対象フレーム・カメラ・レンダリング設定を固定した比較。
3. **知覚的評価:** SSIM等による許容範囲評価。指標の数値だけで意味的に正しい描画とはしない。
4. **レンダリング診断:** GPU実測、GPUキャプチャ、ドローコール、Pass、RT、Shader Variant、オーバードローなど。
5. **人間のレビュー:** 視覚的違和感、表現意図、意匠の変化など自動比較が判断しきれない領域。

## 2. 撮影条件を固定する

ゲーム版、シーン、カメラ、座標、解像度、色空間、HDR/SDR、ポストプロセス、時刻、乱数シード、描画API、ドライバ、GPU、OS、フレーム番号をEvidenceに含める。不一致時は性能劣化か環境差かを区別する。

## 3. 誤検知対策

動くUI、時間依存エフェクト、アンチエイリアシング、浮動小数誤差、非決定的パーティクルを無条件の失敗にしない。Maskや許容閾値は監査可能とし、広すぎるマスクで退行を見逃さないこともテストする。

## 4. 実GPU検証で必要なこと

- 対象GPU・ドライバ・APIを明記する。
- FPS平均だけでなくFrame Time分布、hitch、CPU/GPUのボトルネックを保存する。
- GPUキャプチャツールの実データと、ファイルのハッシュ、対象ビルドSHAを対応付ける。
- 外部ツールの終了コードが0でも、有効なキャプチャ／必須マーカーが欠けた場合は成功扱いしない。
- 商用ゲームのキャプチャ・素材の権利、機密性、再配布可否を事前確認する。

## 5. 受け入れ条件

代表的な正常画像・異常画像・異なるGPU環境・非決定的エフェクトを用意し、Precision/Recallと失敗理由を比較する。実GPUを使わないケースは`Runtime Verified`と称さない。

関連：[RFC-003-GPU-VISUAL-VERIFICATION](../rfcs/RFC-003-GPU-VISUAL-VERIFICATION.md)。
