# PRD-001: 製品対象・利用者・成功条件

**Status: Proposed** | **Priority:** 基盤要件 | **Scope:** 将来のサービス化

## ユーザーとジョブ

| ペルソナ | ジョブ | 想定する成果 |
|---|---|---|
| 個人ゲーム開発者 | CIやQAの実行方法がばらばら | 単一ダッシュボードで検査状況を確認 |
| ゲームQA担当 | 再現しづらい不具合を管理 | 再現条件、ログ、改訂版、修正後の結果を辿る |
| TA／アーティスト | アセットや描画の退行を把握 | 比較可能な指標・スクリーンショット／キャプチャ |
| テックリード | 完了申告が実際に裏付けられているか知りたい | ClaimとEvidenceを分けて検討 |
| リリース担当 | 重大な未解決項目を見落としたくない | 必須検査と承認条件に基づくGo/No-Go |
| 運用管理者 | 監査・利用量・権限を統制したい | テナント境界と操作証跡 |

## 最初の価値検証

- QA結果を同じプロジェクトと対象SHAへ紐付けられる。
- テスト失敗／環境不備／未実行／結果不明を明確に区別する。
- 進捗申告が重大なEvidenceと矛盾した場合、理由を説明できる。
- AIは調査・修正候補の役割にとどまり、実行と検証結果を出力してから人が判断する。
- 初期導入時の既存ツールを置換せず、連携・情報統合を優先する。

## 非機能要件（数値は未確定）

- データ権限: 認証・認可・組織境界・プロジェクト権限の検証可能性
- 信頼性: 再試行・冪等性・バックアップと復元・監視
- 可用性: 正式SLOは試験と運用体制の検証後に定義
- 性能: バックログ件数、同時実行数、Evidence量を変えた測定
- セキュリティ: 解析対象が悪意のあるコードでもホストに影響させない隔離方針
- 費用: 保存容量、外部計算、LLM利用量の可視化と上限

## 対象外

GitHub/Jiraの全面代替、完全自律的な無承認マージ、人の働きぶりのランキング、全GPU／ゲーム機での自動品質保証を初期製品の要件としない。

## 完了条件

利用者シナリオ、負荷・機能・安全性の検証計画、プライバシー上の要件、優先順位、除外範囲が各専門資料に関連付けられていること。実装完了とは独立したPRDの完成条件とする。
