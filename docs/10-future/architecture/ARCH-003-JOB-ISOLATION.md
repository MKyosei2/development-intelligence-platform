# ARCH-003: 不信頼コードを扱うQAジョブの隔離

**Status: Proposed / Security-Critical**

## 1. 脅威モデル

DIPは第三者のソース、ビルド、テストコマンド、ゲーム実行ファイルを扱う可能性がある。これらをホスト上で無制限に実行すると、秘密情報の流出、横断的なファイルアクセス、ネットワーク攻撃、資源枯渇、改ざんが発生し得る。

## 2. 安全境界の原則

- 既定は**実行拒否（fail-closed）**。要求された隔離が利用不可なら、黙ってホスト実行へ降格しない。
- 信頼レベルに応じて、実行許可されたコマンドと必要なリソースを明示する。
- 書き込み可能なワークスペースを使い捨てにし、ソース本体を汚染しない。
- 実行時間、CPU/GPU、メモリ、プロセス数、ディスク、成果物サイズに上限を設定する。
- ホストの認証情報、SSH鍵、クラウドメタデータ、組織内部ネットワークへの到達を遮断する。
- ネットワークとファイルシステムの隔離を**実際に検証**し、設定値だけで有効と推定しない。
- 中断・キャンセル・Worker死亡時にプロセスツリーと実行環境を回収する。

## 3. 候補の実行方式

| 方式 | 用途 | 未解決の課題 |
|---|---|---|
| 制限付きホスト実行 | 信頼済みローカル開発のみ | 第三者コードには不十分な可能性 |
| OCIコンテナ | 一般的なCI/QAの隔離候補 | カーネル共有、権限・ネットワーク・mount検査 |
| VM／専用Runner | より強い隔離が必要なゲーム・GPU実行 | 起動時間、GPUパススルー、費用 |

## 4. Evidence

隔離方式、イメージ／VM識別子、許可されたmountとネットワーク方針、対象SHA、ジョブID、検証時刻、タイムアウト、exit code、外部依存の状態、Artifactのハッシュを残す。自己申告する環境変数だけに安全性を依存させない。

## 5. 受け入れテスト

- 実行環境の外側のファイルへ書き込みができない。
- 禁止ネットワークに接続できない。
- 許可されていない環境変数／認証情報を読めない。
- Timeout/Cancel時の子プロセスが残留しない。
- Runner未設定時には`NOT_EVALUATED`/`BLOCKED`相当になり、PASSにならない。
- Worker再試行による副作用の二重実行を防止する。

この文書が存在しても隔離が実装・実証済みとは限らない。既存の実行器と設定を実際に監査してから完了扱いにする。
