# ARCH-005: 可観測性・障害診断・監査

**Status: Proposed**

## 観測の対象

- API: 成功率、エラー率、遅延分布、依存DB状態
- Worker: キュー滞留時間、実行時間、再試行、Lease喪失、隔離失敗
- QA: 検査対象、検査カバレッジ、失敗理由、誤検知・不安定テスト
- Evidence: 改訂版不一致、検証不能、Artifact破損、未評価の割合
- Platform: CPU/RAM/ディスク/ネットワーク、GPU Runner（存在する場合）
- Business: 利用者の同意と許容される範囲で導入・継続利用状況

## 運用ダッシュボードの候補

1. ヘルス: リクエスト・依存先・Workerの現在状態。
2. キュー: 待機、実行中、失敗、キャンセル、DLQ／再実行待ち。
3. Evidence: 正確なrevisionに紐付いた成功・未評価・不正データ。
4. セキュリティ: 認証失敗、権限拒否、隔離逸脱の試行。
5. SLO: 選んだSLIのウィンドウ推移と予算消費。

## 相関ID

RequestId、JobId、TenantId（必要な場合は安全な内部識別子）、ProjectId、SourceSHA、TargetSHA、ArtifactDigestを、機密情報を含めない形で相関可能にする。

## アラートのルール

障害の影響と対応可能性に応じて通知する。単発のログ行で騒音を発生させるのではなく、ユーザー影響、継続時間、誤検知リスクから閾値を決定する。具体値は導入前の負荷試験後に設定する。

## 検証

意図的なDB切断・Worker停止・Artifact異常を発生させ、ログ・メトリクス・トレース・通知・復旧手順が同じ障害を示すことを確かめる。単にライブラリが導入されているだけでは運用実証と見なさない。
